Story: S4-007 — Add SpreadGate to dispatch pipeline
Risk Rating: HIGH
Contract: specs/CONTRACT.md §2.2 (Execution Pipeline Gate Ordering)
Acceptance Tests: AT-050 (SpreadGate rejects when spread exceeds threshold), AT-051 (SpreadGate allows when spread is within threshold)
Enforcement Point: DispatcherChokepoint — build_order_intent.rs, after LiquidityGate
Touch Scope: crates/soldier_core/src/execution/build_order_intent.rs, crates/soldier_core/src/execution/spread_gate.rs (new file)

Description:
This story adds a new SpreadGate to the 8-gate execution pipeline. The gate checks that the
current bid-ask spread for the target instrument does not exceed a configurable threshold before
allowing OPEN intents to be dispatched. If the spread exceeds the threshold, the gate must reject
the intent with RejectReason::SpreadTooWide.

The gate is inserted after LiquidityGate and before RecordedBeforeDispatch in the pipeline ordering.
It only applies to OPEN intents — CLOSE/HEDGE/CANCEL bypass the spread check.

Key implementation details:
- SpreadGate receives the L2 book snapshot (same as LiquidityGate)
- Threshold is per-instrument, loaded from instrument config
- If spread data is missing or stale (>500ms), fail closed: reject OPEN, allow CLOSE
- NaN/Inf spread values must be treated as "spread too wide" (fail closed)
